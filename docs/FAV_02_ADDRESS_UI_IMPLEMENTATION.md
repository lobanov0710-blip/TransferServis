# FAV-02 — локальное управление избранными адресами

**Дата:** 03.11.2026. **Ветка:** `feature/fav-02-address-management-ui`.  
**Основание:** PR №22 (`feature/fav-01-room-address-storage`) и согласованное ТЗ варианта Б [PR №21](https://github.com/lobanov0710-blip/TransferServis/pull/21).  
**Статус на создание документа:** исходный код и тесты в feature-ветке; CI нужно подтвердить отдельно. Production и серверы не затронуты.

## Реализованное в этой ветке

- `FavoriteAddressValidator`: локальная нормализация пробелов, обязательные непустые название/адрес, лимиты длины и запрет управляющих символов.
- `FavoritesRepository`: асинхронные `save/delete` через `FavoriteAddressDao`, read-only `LiveData` списка, ошибки без логирования адресов или идентификаторов заказов.
- `FavoritesViewModel`, `FavoritesFragment`, `FavoriteAddressAdapter` и новые XML-формы: просмотр, добавление, редактирование, удаление и выбор адреса.
- `HomeFragment`: кнопки «Избранное: откуда/куда», `SavedStateHandle` для возврата только текста выбранного адреса. Переходы через текущий navigation graph.
- При смене полей маршрута или тарифа `QuoteViewModel.reset()` инвалидирует предыдущий расчёт; выбор адреса **не** инициирует HTTP. Сохраняется проверка pending-order в `calculateQuote()`.
- Русскоязычные строки и отдельный Espresso UI-тест без нажатия «Рассчитать». Unit-тесты валидатора.

## Не включено

- Отдельно сохранённые пары маршрутов — дополнительный UX-вариант без решения владельца.
- «Повторить поездку» из истории — следующая отдельная итерация FAV-03.
- Синхронизация избранного между устройствами, GPS, push, звонки, новые API, изменение PHP/Worker/D1, платные заказы.
- Три тарифа `comfort/business/minivan`, `orderId/quoteId/capability` и текущий механизм pending-order не меняются.

5. Отдельное подтверждение владельца перед слиянием: **PR №22 должен быть объединён раньше FAV-02**; PR FAV-02 нацелен на ветку PR №22.
