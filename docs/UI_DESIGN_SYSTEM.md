# UI-01 — фирменный стиль Android Transfer Servis

**Статус:** исходная концепция для проверки владельцем; не является разрешением на выпуск APK.

## Основа

- Стек остаётся Java + XML / MVVM / Material3. `applicationId`, API, способы хранения сессии и бизнес-логика заказов не изменяются.
- Название бренда: **Transfer Servis**. Для адаптивной и обычной launcher-иконки используется компактная адаптация сохранённого логотипа «Премиальный логотип Transfer Servis(2).png» от 02.10.2026: автомобиль на золотой дороге и закат под дугой. Для размеров 48–72 dp исключены и слоган, и мелкий wordmark: в иконке остаётся только верхняя автомобильная эмблема на тёмно-графитовом фоне. Композиция размещена внутри центральной зоны, края фото смягчены для масок значков Android. Полная надпись «Transfer Servis» сохраняется в названии приложения и может использоваться на крупных фирменных носителях. Для Android 13+ используется отдельный монохромный векторный знак TS; он не является цветной фотографической версией логотипа.
- Начальный экран: AndroidX SplashScreen без задержки и дополнительных Activity; после запуска используется `Theme.TransferServis`.
- Фирменные цвета: фон `#05080C`, поверхности `#0E141C` / `#151D27`, акцент `#2B7CFF`, вторичный `#D5B06F`, текст `#F5F7FA`. Кнопки с белым текстом: `#1D62D5` (контраст более 4.5:1).
- Общие текстовые стили определены в `styles_ui.xml`; их внедрение в экранные макеты — следующий шаг, без одномоментного рефакторинга экранов.

## Подтверждённая линейка тарифов мобильного приложения

Только **Комфорт**, **Бизнес**, **Минивэн**. Другие тарифы в интерфейс и API текущего Android-приложения не добавлять.

## Ограничения UI-01

- Иконка и splash используют `app/src/main/res/drawable-nodpi/ts_brand_launcher.webp` (компактная производная от оригинального изображения из библиотеки владельца). Ресурсы launcher (обычный/круглый/монохромный), стартовой темы и цветов кнопок изменяются без затрагивания бизнес-логики.
- Не менять модель заявки, серверный тарифный контракт, дату/статус заказа, механизм recovery и токены.
- Не создавать production-заявки в тестах. Подписанный Release APK, публикация и взаимодействие с production не выполняются.

## Перед слиянием

1. GitHub CI: Debug unit, lint и сборка; Release unit, lint, unsigned APK.
2. Проверить иконку на Android 7/8/13+, в том числе themed icons; SplashScreen на Android 7+ (без искусственной задержки).
3. Проверить светлую/тёмную системную тему, системные панели и масштабирование текста на отдельном эмуляторе.
4. Убедиться, что три тарифа и сценарии заказа работают без регрессий; инструментальные тесты запускать только на **изолированном** AVD.

## Автоматизированная визуальная проверка (UI-01)

- `.github/workflows/ui-visual-smoke.yml` запускает временный отдельный Android 15 (API 35) AVD на GitHub Actions. Он **не использует локальный эмулятор владельца**.
- `scripts/ui-visual-smoke.sh` устанавливает **Debug** APK с безопасным `.invalid` staging URL, фиксирует видеозапись первого запуска и скриншоты главного экрана и системной страницы приложения (иконка/название).
- В workflow **нет** оформления заявки, записи в production, передачи access-токенов или запуска полного набора инструментальных тестов.
- Артефакт: `ui01-emulator-screenshots-api35` (скриншоты, `launch.mp4`, вывод `am start`, 14 дней).
- Успех smoke CI **не заменяет визуальное ревью**: проверить маску иконки, масштаб и читаемость на записях перед merge. Тест API 35 не охватывает Android 7 и themed icon Android 13; для них остаётся отдельный контроль.

## Дальнейшие этапы

- **UI-02:** главная, карточки тарифов, результат расчёта (только визуальная переработка, без смены API).
- **UI-03:** бронирование, подтверждение, активная поездка; защита от повторного POST неизменна.
- **UI-04:** история, профиль, нижняя навигация, системные отступы и состояния ошибок.
- **UI-05:** доступность, адаптивность, instrumented regression, физическое устройство и release readiness.
