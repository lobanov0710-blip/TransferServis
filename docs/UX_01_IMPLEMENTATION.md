# UX-01 — реализация утверждённых экранов

Дата: 27.11.2026. Ветка: `feature/ux-01-approved-passenger-ui`.
Основа: PR №40, `2c025565bb2fb294359e8857c703be415abd6191`.
Владелец отдельно утвердил первый пакет и PDF с 9 макетами.

## Подготовлено

- Шесть основных экранов на Java/XML с общими стилями, исходной палитрой, адаптивными тарифами и кнопками с минимальной высотой вместо жёсткой.
- Карточка своего текущего заказа до формы расчёта; recovery имеет прежний приоритет.
- Компактное избранное с отдельными подписями TalkBack и областями нажатия от 48 dp.
- Локальная история по месяцам, существующий повтор done, вход только в заказ текущей проверенной сессии.
- Время последней успешной проверки; при временной ошибке остаётся разрешённый снимок той же сессии. Он хранится только в памяти, не добавляет новую базу или резервное копирование.
- Одно выполняющееся чтение статуса на сессию: события жизненного цикла/обновления присоединяются к запросу. Обработанный результат защищён generation/session проверками. Автоматического polling и повторной подачи заказа нет.
- При 401/403, недействительном ответе, смене orderId/token/expiry снимок не выдаётся. Сетевая ошибка не означает отмену.

## Проверки

Локально: XML и ссылки на ресурсы, `bash -n`, `git diff --check`.
Android SDK отсутствует; загрузка Gradle недоступна, поэтому локальные Android unit/Lint/APK не объявляются успешными.

CI: стандартные Debug/unsigned Release проверки и отдельный `UX-01 approved passenger UI` на одноразовом API35 AVD. Новый UI workflow выполняет 8 относящихся к пакету/восстановлению тестов в трёх конфигурациях: 360dp/100%, 360dp/200%, 411dp/130%. Сохраняются реальные снимки Android и XML-отчёты. Зелёный CI не заменяет просмотр изображений и физическое устройство.

Результаты CI фиксируются только после завершения на конечном SHA. Сейчас проверки ожидаются.

## Границы

Контракт API, backend, БД, release-конфигурация, FCM, тарифы и права не менялись. Серверные время подачи, пожелания, карта, чат и звонки этим PR не реализуются. Не объединять автоматически с отдельной PUSH/security/release цепочкой; при интеграции обязательно сохранить ранее подготовленный origin guard из PR №35/№39.

Все UI-данные в тестах демонстрационные. Сценарии очищают локальные тестовые данные и допускаются исключительно на одноразовом CI AVD, не на устройстве владельца. Реальные заявки и уведомления отсутствуют.
