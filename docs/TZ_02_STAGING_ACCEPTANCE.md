## Допуск к проверке на сервере

1. Сверить фактическую схему выделенного STAGING D1 с закреплённым G2 и идентичность базы с планом приёмки. Для существующей G2-инвентаризации использовать уже утверждённый [Windows-сценарий](https://github.com/lobanov0710-blip/uber-v3/blob/a0d309d31c3f7e3fc2ea278d00e5329b2c76cdb0/docs/G2_PRIVATE_INVENTORY_HANDOFF_2026-11-19.md). Квитанция подтверждает распознанный профиль на дату чтения. Для допуска проверить точную цепочку миграций выбранного контура и наличие допустимого синтетического назначения. Закрытый отчёт остаётся у владельца.
2. Подтвердить, что отдельный Worker обслуживает только маршрут чтения v2 и использует новую D1. Режим `ADMIN_PHONE_TEST_ONLY=true` действующего Worker для Admin сохраняется.
3. Проверить синтетический заказ, допущенные автомобиль и водителя, отдельные тестовые реквизиты и версию Android. В конфигурации нового Worker предусмотрен флаг `PASSENGER_ASSIGNMENT_V2_ENABLED=true`. На PHP наличие и значение файла `passenger-qa-upstream.txt` контролирует доступность выделенного маршрута без изменения общего флага.

## Сборка для владельца

Для приёмки используется [отдельная QA-сборка](TZ_02_ISOLATED_QA_RUNBOOK.md#порядок-развёртывания). Ранее проверенный opt-in APK `.staging` относится к прежнему пути на этом хосте. Данные предыдущей сборки сохранены ниже для сверки.

```powershell
.\gradlew.bat :app:assembleDebug '-PtransferPassengerStatusV2=true' '-PtransferStagingBaseUrl=https://staging.transfer-servis52.ru/'
Get-FileHash .\app\build\outputs\apk\debug\app-debug.apk -Algorithm SHA256
```

При добавлении тестового токена через локальные свойства APK остаётся у владельца. [Приёмочный CI №46113559887](https://github.com/lobanov0710-blip/TransferServis/actions/runs/46113559887) прошёл на `f4b62b13e057249dc081bcb63da7375659dc390a`. Собран APK с включённым v2 и пустым токеном, подтверждены отказ от другого адреса, отсутствие перенаправления, пакет `.staging` и отладочная подпись. [Архив CI](https://github.com/lobanov0710-blip/TransferServis/actions/runs/46113559887/artifacts/15250891677) хранится до 12.12.2026. В случае конфликта подписи установленной `.staging` версии записать сообщение установщика и сохранить существующие локальные данные.

## Критерии на физическом телефоне

| Сценарий | Ожидаемый результат |
| --- | --- |
| Запуск отладочного APK | Открывается `ru.transferservis.app.tz02qa`. |
| Синтетический заказ до назначения | На экране есть статус, карточка автомобиля скрыта. |
| Назначение допущенной машины тестовым оператором | После одного ручного обновления видны доступные сведения и согласованный госномер этой машины. |
| Разрешённое переназначение в статусе `taken` | Следующее ручное обновление показывает новую машину. Прежняя карточка исчезает. |
| Потеря сети и ручное обновление | Видны время последней успешной проверки и данные поездки. Госномер и сведения о назначении скрыты. |
| Возврат сети и ручное обновление | Отображается актуальная карточка, если назначение ещё действует. |
| Отзыв доступа, отмена или завершение | Карточка не отображается. |

Фиксируются модель телефона, версия Android, SHA-256 APK, версии тестовых компонентов и результаты сценариев. Токены, персональные данные и скриншоты с реальными заказами в отчёт не входят. При сбое сначала фиксируется этап и код ответа. Отключение v2 и возврат к зафиксированной конфигурации выполняются только в согласованном тестовом контуре, с проверкой штатного v1. Откат схемы D1 требует отдельной процедуры.
