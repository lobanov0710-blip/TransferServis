# PROD-SMOKE-01 — контрольная проверка Android с рабочим API (эмулятор)

**Цель:** выяснить, почему заявки из Android не видны в действующем Telegram-боте Transfer Servis, когда заявки с сайта приходят. Это **не** выпуск, подписание Release APK или публикация приложения.

## Почему обычный Debug не подходит

- `debug` по утверждённой архитектуре обращается только к `https://staging.transfer-servis52.ru/` и имеет пакет `ru.transferservis.app.staging`.
- В staging Telegram-уведомления выключены по умолчанию. Это не означает неисправности production-бота.
- `release` обращается к `https://transfer-servis52.ru/`, но Release APK остаётся **неподписанным и непригодным для установки** без отдельной release-подписи, которая сейчас отложена.

## Изолированная временная сборка productionSmoke

Только при явной Gradle-опции `-PtransferProductionSmoke=I_ACKNOWLEDGE_PRODUCTION_ORDERS` создаётся дополнительный тип сборки `productionSmoke`.

| Параметр | productionSmoke |
|---|---|
| `applicationId` | `ru.transferservis.app.productiontest` |
| Название под иконкой | `Transfer Servis (ПРОД-ТЕСТ)` |
| HTTPS API | `https://transfer-servis52.ru/` |
| `STAGING_ACCESS_TOKEN` | пустой |
| Ключ установки на эмулятор | **стандартный debug-ключ Android**, не production-keystore |
| Доставка приложения клиентам | запрещена |
| Автоматическая отправка заказа сборкой / CI | отсутствует |

**Важное разграничение:** для установки Android требует подписанный APK; в данном случае Gradle использует **обычную отладочную подпись**, не создавая и не используя личный release-keystore владельца. Это не подписанный Release APK. Нельзя использовать такой файл как публичный релиз.

Сборка не заменит `ru.transferservis.app` и `ru.transferservis.app.staging`, поскольку у неё отдельный package ID и хранилище. Существующие `debug` и `release` не изменены; в обычной Gradle-синхронизации дополнительного варианта нет.

## Подготовка локального эмулятора на Windows

Сначала принять PR и синхронизировать `master`, либо проверить отдельную ветку PR без слияния. **Нельзя отправлять производственный заказ без отдельного согласия владельца**, потому что он попадёт в production D1, может вызвать действующий Telegram и Firebase-уведомления водителям.

Из корневой папки `TransferServis` (секреты не нужны):

```powershell
.\gradlew.bat -PtransferProductionSmoke=I_ACKNOWLEDGE_PRODUCTION_ORDERS :app:testProductionSmokeUnitTest :app:assembleProductionSmoke
```

После успешной сборки установить APK **только на эмулятор**, не стирая текущие приложения:

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" -s emulator-5554 install -r ".\app\build\outputs\apk\productionSmoke\app-productionSmoke.apk"
```

Сначала убедиться в приложении с подписью `(ПРОД-ТЕСТ)`. До получения отдельного разрешения проверять только открытие приложения, навигацию и отсутствие staging-токена. Ручное нажатие «Рассчитать» также обращается к живому production API, поэтому тест сетевых запросов проводим только после согласования объёма. Кнопка отправки заказа **создаёт настоящую заявку**, а не имитацию.

## Приёмка после отдельного разрешения на одну реальную тестовую заявку

1. Согласовать тестовые имя и номер телефона, маршрут, дату, отсутствие реальных персональных данных, а также возможное уведомление действующих водителей. Не использовать чужие номера.
2. На эмуляторе войти в `Transfer Servis (ПРОД-ТЕСТ)`, выполнить расчёт, отправить **одну** явно помеченную `ПРОВЕРКА ANDROID PROD-SMOKE-01` заявку.
3. Зафиксировать присвоенный `orderId` в UI и сравнить с записью production D1. Проверить, появился ли соответствующий ID в рабочем Telegram-чате.
4. Если заказ в production D1 присутствует, а Telegram молчит, проверить серверный лог `TELEGRAM SENT` / `ORDER TELEGRAM ERROR`. HTTP-успех заказа не гарантирует доставки Telegram.
5. Не отправлять повторно новую заявку при неизвестном результате: использовать существующее восстановление заказа по его исходному `quoteId`/сохранённому payload.
6. По завершении удалить только тестовую установку `ru.transferservis.app.productiontest` (не трогать данные работающих Debug и Release).

**Это временная диагностическая процедура, не изменение схемы production.** Никакие серверные секреты, URL PHP и Worker, production БД, Telegram или FCM не изменяются. Пока реальная проверка не выполнена, доставку заявок из Android production считать неподтверждённой.
